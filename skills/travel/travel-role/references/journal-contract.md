# Контракт журнала наблюдений

Файл: `/opt/data/travel/observations.jsonl`, одна строка JSON на одно
наблюдение. Строки пишут скрипты-источники из `scripts/` (они же ставят
`id`, `ts`, `price_prefix`); наблюдение, снятое браузером, и суммы —
`scripts/journal_add.py`. Руками JSON не набирается.

## Обязательные поля

| поле | что в нём |
|---|---|
| `id` | `<ts-компакт>-<4 случайных>`, уникален в файле: `20260910T140023-a7f2` |
| `kind` | `fare` цена перевозки на запрошенные даты · `fee` доплата · `forecast` прогноз · `benchmark` уровень цен · `other_date` цена на другие даты · `diff` разность двух чисел журнала · `lead` наводка из ленты распродаж · `rate` курс валюты к злотому |
| `run` | идентификатор прогона, одинаковый у всех строк одного запроса: ts-компакт первой строки |
| `ts` | ISO 8601 с зоной: `2026-09-10T14:00:23+02:00` |
| `source_id` | только из словаря ниже |
| `url` | адрес с параметрами запроса, а не голый эндпоинт; `null` только у CALC |
| `route` | `WAW-BUD`, коды IATA; у `lead` — вылет и совпавшее слово: `WAW-tajlandia`; у `rate` — пара валют: `EUR-PLN` |
| `dates` | только ISO: `2026-09-18` или `2026-09-18/2026-09-20`; у `lead` — дата публикации наводки, даты поездки остаются в `raw`; у `rate` — дата курса |
| `pax`, `value`, `currency` | число пассажиров (у `rate` — `null`), число, валюта источника кодом ISO: `PLN`, `EUR` |
| `status` | `ORIENTIR` · `QUOTED` · `CONFIRMED` · `CALC` |
| `price_prefix` | `od`, если в тексте источника есть рекламное «от», иначе `null` |
| `raw` | текст источника как он есть, без перевода |

Словарь `source_id`: `google_flights`, `google_flights_trains`,
`ryanair_site`, `ryanair_api`, `flixbus_api`, `wizzair_site`, `wizzair_api`,
`lot_site`, `kiwi_mcp`, `azair_site`, `fly4free_pl_feed`, `fly4free_com_feed`,
`wakacyjnipiraci_feed`, `holidaypirates_feed`, `pepper_feed`,
`travelpayouts_api`, `nbp_api`, `web_site` (страница любого сайта «с глаз»: `url` и `raw`-фрагмент обязательны, статус не выше QUOTED, валюта источника — `--currency`), `CALC`.
Суффикс должен сходиться с url: `_api` — только для адресов API,
`_site` — только для страниц сайта, `_feed` — запись RSS-ленты. Страница
бронирования Ryanair — это `ryanair_site`, не `ryanair_api`; у строки `ryanair_api` страница выбора рейса лежит в `link` (для `[ссылка id]`). У `kiwi_mcp`
url — `bookingUrl` из ответа Kiwi. Какой скрипт какой `source_id` пишет —
`references/sources.md`.

Дополнительно: `currency_observed: false`, если валюта в ответе источника
пустая и взята из параметра запроса (Google через fast-flights);
`request` — тело запроса у источников с POST (`wizzair_api`), тогда url —
эндпоинт; `self_transfer_allowed` — у `kiwi_mcp`, был ли разрешён
self-transfer в запросе: `true` значит, что вариант может быть связкой
раздельных билетов; у `azair_site` — `true`, когда связка состоит из
нескольких билетов (AZair всегда продаёт плечи порознь, опоздание на
стыковку — риск пассажира); `matched` — слова задачи, по которым найдена наводка;
`link` — страница для человека, когда url — API: у `travelpayouts_api`
выдача Aviasales (url строки — сам запрос к API без токена), у
`wizzair_api` форма покупки Wizz с подставленными маршрутом, датой и
пассажиром; `[ссылка id]` в отчёте берёт `link`, потом `url`. Строки `travelpayouts_api` всегда ORIENTIR: это
кэш чужих поисков за 48 ч, а не выдача на запрос. Строки `azair_site` тоже всегда ORIENTIR: AZair
отдаёт свой кэш цен лоукостеров с возрастом проверки (в `raw` — «checked N h ago»), `link` —
постоянная ссылка на связку (`flightsID`), покупка плеча — редиректом на перевозчика.

## Ссылки между строками

- `kind: fee` обязана нести `of` — id строки, на которой доплата
  наблюдалась. `route`, `dates` и `source_id` доплаты совпадают со
  строкой, на которую она ссылается.
- Доплату с одного рейса не подставляешь в сумму по другому: если в
  `inputs` есть доплата, там же должна быть и её собственная строка.
- `status: CALC` требует `inputs` (id слагаемых, не ts) и `operator`:
  `sum`, `diff` или `convert`.
- У `diff` ровно два операнда, в порядке «уменьшаемое, вычитаемое»:
  значение равно `inputs[0] − inputs[1]`.
- Операнды `sum` и `diff` — в одной валюте, она же у строки CALC.
- У `convert` ровно два операнда: наблюдение в чужой валюте и строка
  `rate` с парой `<валюта наблюдения>-PLN`; значение равно
  `inputs[0] × inputs[1]`, `currency` — `PLN`.
- `diff` между разными `route` или `dates` — это не экономия, а разные
  поездки. Такую строку либо не пишешь, либо помечаешь
  `comparable: false` и в отчёте называешь обе разницы.
- `inputs` и `of` ссылаются только на строки своего прогона.

## Образцы

Наблюдение:
```json
{"id":"20260910T140023-a7f2","kind":"fare","run":"20260910T140023","ts":"2026-09-10T14:00:23+02:00","source_id":"google_flights","url":"https://www.google.com/travel/flights?q=...&curr=PLN","route":"WAW-BUD","dates":"2026-09-18/2026-09-20","pax":1,"value":608,"currency":"PLN","status":"QUOTED","price_prefix":null,"raw":"608 zł"}
```
Доплата:
```json
{"id":"20260910T140047-c9d4","kind":"fee","run":"20260910T140023","ts":"2026-09-10T14:00:47+02:00","source_id":"flixbus_api","url":"https://global.api.flixbus.com/search/service/v4/search?from_city_id=...&currency=PLN","route":"WAW-BUD","dates":"2026-09-18","pax":1,"value":3.99,"currency":"PLN","status":"QUOTED","price_prefix":null,"of":"20260910T140023-a7f2","raw":"opłata platformowa 3,99"}
```
Сумма:
```json
{"id":"20260910T140105-b3e1","kind":"fare","run":"20260910T140023","ts":"2026-09-10T14:01:05+02:00","source_id":"CALC","url":null,"route":"WAW-BUD","dates":"2026-09-18/2026-09-20","pax":1,"value":611.99,"currency":"PLN","status":"CALC","price_prefix":null,"operator":"sum","inputs":["20260910T140023-a7f2","20260910T140047-c9d4"],"raw":"608+3,99"}
```

## Валюта не PLN

Цена в чужой валюте пишется как есть, со своей `currency`. В отчёт число
идёт только в злотых — через строку `convert`: курс — строка `rate` от
`nbp_api` (таблица A НБП, средний курс, дата курса в `dates`), значение —
цена × курс. Скрипт-источник пишет все три строки сам (`wizz_farechart.py`
для обратного плеча из-за границы); наблюдение браузером в чужой валюте
описываешь словами и держишь в «не проверено:». В отчёте рядом с числом
в злотых называешь сумму в валюте и курс — каждое со своим id — и
оговариваешь: точную сумму в злотых продавец выставит по своему курсу
при оплате.

Курс:
```json
{"id":"20260913T201500-r4te","kind":"rate","run":"20260913T201455","ts":"2026-09-13T20:15:00+00:00","source_id":"nbp_api","url":"https://api.nbp.pl/api/exchangerates/rates/a/eur/?format=json","route":"EUR-PLN","dates":"2026-09-11","pax":null,"value":4.3228,"currency":"PLN","status":"QUOTED","price_prefix":null,"raw":"NBP 177/A/NBP/2026 2026-09-11 EUR mid 4.3228"}
```
Пересчёт:
```json
{"id":"20260913T201501-c0nv","kind":"fare","run":"20260913T201455","ts":"2026-09-13T20:15:01+00:00","source_id":"CALC","url":null,"route":"BCN-WAW","dates":"2026-10-30","pax":1,"value":177.23,"currency":"PLN","status":"CALC","price_prefix":null,"operator":"convert","inputs":["20260913T201458-eu41","20260913T201500-r4te"],"raw":"41.00 EUR × 4.3228"}
```

## Коды проверки

Структура: `E001` не-JSON · `E100` строка в окне прогона без своего `run`
· `E101` `dates` не ISO · `E102` `source_id` вне словаря · `E103` суффикс
`source_id` не сходится с url · `E104` наблюдение без url · `E105` `value`
не число.

Цена из raw: `E200` в тексте «od/from/ab/от», а статус выше ORIENTIR ·
`E201` тот же маркер при пустом `price_prefix` · `W202` валюта не
наблюдалась.

Арифметика и связи: `E300` CALC без `inputs` · `E301` нет `operator` ·
`E302` пересчёт не сходится · `E303` ссылка за пределы прогона · `E304`
`diff` по разным route/dates без `comparable: false` · `E305` `fee` без
`of` · `E306` `of` ведёт на чужую строку · `E307` доплата в сумме без
своего рейса · `E308` id дважды в `inputs` · `E309` операнды `diff`
переставлены · `E310` валюты операндов `sum`/`diff` или строки CALC
различаются · `E311` `convert` не из наблюдения и строки `rate` с парой
под его валюту · `E312` слагаемое `sum` снято на даты вне дат суммы
(запас в сутки — только автобусу `flixbus_api`: ночной рейс к утреннему
вылету; билет лежит строго в датах суммы).

Отчёт: `E400` число без `[id]` · `E401` id не резолвится · `E402` число не
равно `value` (целое в тексте — округление до злотого, с копейками — точно) ·
`E403` ярлык статуса в тексте не совпадает с журналом · `E405` сообщение до
маркера `--- приложение ---` длиннее 20 непустых строк · `E406` `[ссылка id]`
не ведёт на строку прогона со страницей продавца (link и url пусты, адрес API или строка ORIENTIR) · `E407` число из карты минимумов Wizz (`wizzair_api`) — само или через `convert`/`sum`/`diff`; карта — матрица дат и ссылка, цена плеча — строка `google_flights` · `E408` `[ссылка]` на строку Kiwi с рейсами только Wizz Air/Ryanair — посредник, покупка у перевозчика · `E410` «обратно из <домашний аэропорт>» — обратное плечо прилетает, «обратно в …» · `E411` плечо Wizz/Ryanair в цене, показанной в сообщении, без `[ссылка id]` на wizzair.com/ryanair.com по тому же маршруту и дате. Плечи берутся из журнала, не из слов сообщения: у `ryanair_api`/`ryanair_site` — по route и dates, у `google_flights` — по имени перевозчика в raw; у CALC — по inputs до листьев; дата через «/» — два плеча. Строки, начинающиеся с «Другие даты», не считаются. Google и Kiwi — не продавцы · `E412` в цене, показанной в сообщении (CALC — до листьев, «Другие даты» тоже), строка Kiwi, у которой все сегменты — рейсы Wizz Air/Ryanair (по плечам и кодам рейсов в raw: `FR` → Ryanair, `W6` → Wizz) или в raw не назван перевозчик вне Wizz/Ryanair (кодов нет — перепродажа не опровергнута): Kiwi не продавец прямых перевозчиков, цена плеча — у перевозчика (`ryanair_api`/`ryanair_site`, `google_flights --airline`), выдача Kiwi — в приложение. Связка Kiwi с другим перевозчиком — товар Kiwi, её цена и ссылка идут как есть · `W404` сколько наблюдений прогона не вошли
ни в отчёт, ни в расчёты (одной строкой, по источникам).

Предупреждения (`W`) отчёт не блокируют. `W404` — справка, не требование:
выносить эти наблюдения в отчёт не нужно.
