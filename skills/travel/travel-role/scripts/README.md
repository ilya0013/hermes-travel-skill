# Скрипты роли: источники, журнал, проверка

Скрипты-источники (`kiwi_search.py`, `ryanair_fares.py`, `google_flights.py`,
`wizz_farechart.py`, `azair_search.py`, `deal_feeds.py`, `flixbus_fares.py`), ручная строка
`journal_add.py`, тик дозора `watch_route.py` и свод по интересам (`deal_feeds.py --interest`,
обёртка cron `/opt/data/scripts/travel/interest_digest.sh`) пишут журнал через общий `journal.py`; что каждый
даёт и как звать — `../references/sources.md`. Запускаются venv источников
`/opt/data/travel/lib/venv`, не Python Hermes. Их модульные тесты — `tests/test_travel_scripts.py`
в репозитории.

## Отчёт для человека: report_render и drive_report

Файл отчёта `reports/<run>.md` — сообщение (до строки `--- приложение ---`, не больше 20 непустых
строк) и приложение. Числа в обеих частях с `[id]`, ссылка на покупку — `[ссылка <id>]`.

- `report_render.py --journal J --report R [--details-url URL]` — сообщение без id, `[ссылка id]`
  заменена на страницу продавца из строки журнала (`link`, иначе `url`), последней строкой
  «Подробно → URL».
- `run_show.py [--journal J] [--run ID] [--source SID]` — строки прогона одним экраном (id, цена, статус,
  «ссылка» у строк со страницей продавца по условию E406) — чем агент смотрит журнал перед отчётом
  вместо heredoc, на который Hermes останавливается за разрешением.
- `drive_report.py --journal J --report R --title "<дата> <маршрут> <окно>"` — весь файл без маркера
  Google-документом в папке «Поездки» на Диске владельца (папка создаётся сама). Ходит токеном
  агента через `build_service` скилла `google-workspace`, поэтому запускается питоном Hermes:
  `HERMES_HOME=/opt/data /opt/hermes/.venv/bin/python3 drive_report.py …`. Печатает `doc_url`.
  Тесты — `tests/test_report_for_human.py` в репозитории.

## verify_v3 — проверка журнала и сверка отчёта

Проверяет не только журнал наблюдений, но и текст отчёта против него.
Отчёт без ссылок на id непроверяем — это и есть дыра, через которую в прогоне 6
прошли числа, которых в журнале нет.

## Запуск

    python3 verify_v3.py --journal /opt/data/travel/observations.jsonl \
                         --run 20260910T165447 \
                         --report /opt/data/travel/reports/20260910T165447.md

Без `--run` берётся последний прогон в файле. Без `--report` слой 4 не выполняется.
Код возврата: 0 — ошибок нет, 1 — есть ошибки.

## Тесты

    python3 make_fixtures.py && python3 run_tests.py

Фикстуры перечислены в `EXPECTED` внутри `run_tests.py`, у каждой ожидается ровно свой
набор кодов. Ложное срабатывание на `clean` — такой же провал, как пропущенный дефект.
Новый источник — это новый `source_id` в `verify_v3.py`, строка в `journal-contract.md`
и фикстура здесь; источник без фикстуры считается неустановленным.

    python3 make_run6.py
    python3 verify_v3.py --journal fixtures/run6_real.jsonl --report fixtures/run6_report_real.md

Регрессия на реальном прогоне 6, который verifier v2 прошёл чисто.

## Коды

Слой 1 — структура: E001 не-JSON · E100 строка в окне прогона без своего run ·
E101 dates не ISO · E102 source_id вне словаря · E103 суффикс source_id не сходится с url ·
E104 наблюдение без url · E105 value не число

Слой 2 — цена из raw, а не из полей: E200 маркер «od/from/ab/от» при статусе не ORIENTIR ·
E201 тот же маркер при пустом price_prefix · W202 валюта не наблюдалась

Слой 3 — арифметика и связи: E300 CALC без inputs · E301 operator не задан ·
E302 пересчёт не сходится · E303 ссылка за пределы прогона · E304 diff по разным route/dates
без comparable:false · E305 fee без of · E306 of ведёт на чужую строку ·
E307 доплата в сумме без своего рейса · E308 id дважды в inputs · E309 операнды diff переставлены

Слой 4 — отчёт против журнала: E400 число без [id] · E401 id не резолвится ·
E402 число не равно value (целое в тексте — округление до злотого) · E403 ярлык статуса не
совпадает · E405 сообщение до маркера длиннее 20 непустых строк · E406 [ссылка id] не на страницу продавца (link и url пусты, адрес API или строка ORIENTIR) ·
E407 число из карты минимумов Wizz, само или через CALC (карта — даты и ссылка, цена — google_flights) ·
E408 [ссылка] на Kiwi с рейсами только Wizz Air/Ryanair (посредник) · E410 «обратно из <домашний
аэропорт>» · E411 плечо Wizz/Ryanair в показанной цене (по журналу: строки ryanair_*, google_flights с именем
перевозчика; через CALC до листьев) без [ссылка] на wizzair.com/ryanair.com по тому же маршруту и дате —
строки «Другие даты» не считаются · E412 в показанной цене (через CALC до листьев, «Другие даты» тоже)
строка Kiwi с рейсами только Wizz Air/Ryanair (по кодам рейсов в raw; без кодов и без имени другого
перевозчика — тоже) — Kiwi не продавец прямых
перевозчиков, цена плеча у перевозчика ·
W404 сколько наблюдений никуда не вошли (одной строкой, справка)

## Что требуется от роли

1. Каждое число в отчёте — в форме `313,08 [20260910T165523-adt3]`.
2. Отчёт сохраняется в `reports/<run>.md` и проверяется вместе с журналом.
3. У каждой строки CALC — поле `operator`: `sum` или `diff`; у diff операнды в порядке
   уменьшаемое, вычитаемое.
4. `dates` только ISO. `source_id` только из словаря. `price_prefix` заполняется, когда
   в raw есть «od».
